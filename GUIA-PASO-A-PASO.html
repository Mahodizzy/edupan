EduPan PPX · Guía paso a paso

Cómo poner el panel en internet (Netlify), conectar la base de datos en la nube (Firebase) y empezar a usarlo. Es el mismo esquema de Refills EC: la página vive en Netlify y los datos en Firebase de Google. Tiempo estimado: 30 a 40 minutos, una sola vez.

Resumen de lo que vas a hacer

  1. Crear el proyecto de Firebase
  2. Registrar la app web y copiar su configuración
  3. Activar el login (Google y correo)
  4. Crear la base de datos y pegar las reglas
  5. Pegar la configuración en config.js
  6. Subir la carpeta a Netlify
  7. Autorizar la dirección de Netlify en Firebase
  8. Primer ingreso de Ely
  9. Dar acceso al jefe
  10. Respaldos
  11. Cómo actualizar la página después
  12. Si algo falla
Qué necesitas: la carpeta edupan-ppx descomprimida, una cuenta de Google (puede ser la de Ely o la tuya) y tu cuenta de Netlify (la misma de Refills sirve).

¿Ya tenías instalada la versión anterior?

Esta versión agrega reportes diarios (ingresos y egresos por categoría) y roles de pago. Solo haz esto (5 minutos):

  1. Reglas nuevas (obligatorio): Firebase → Firestore Database → Reglas → borra todo, pega el firestore.rules de esta carpeta y toca Publicar. Sin esto, los reportes diarios y los roles no se guardan («La base de datos rechazó la operación»).
  2. Copia tu assets/js/config.js (el que ya tiene tus datos de Firebase) dentro de esta carpeta nueva.
  3. Netlify → tu proyecto → Deploys → arrastra la carpeta nueva (paso 11).

Lo que ya estaba registrado se mantiene. Si es una instalación nueva, sigue los 12 pasos de abajo.

1Crear el proyecto de Firebase

  1. Entra a console.firebase.google.com con tu cuenta de Google.
  2. Toca Crear un proyecto (o Agregar proyecto).
  3. Nombre: edupan-ppx (Firebase puede agregarle letras al final; no importa).
  4. Google Analytics: desactívalo (no hace falta) y toca Crear proyecto.
Es un proyecto nuevo, separado del de Refills: así los datos de EduPan no se mezclan con los de la tienda.

2Registrar la app web y copiar su configuración

  1. En la pantalla principal del proyecto toca el ícono </> (Web).
  2. Apodo de la app: EduPan panel. No marques “Firebase Hosting” (usamos Netlify). Toca Registrar app.
  3. Aparece un bloque de código con const firebaseConfig = { … }. Copia solo lo que está entre las llaves y guárdalo en un bloc de notas. Se ve así: 
    apiKey: "AIzaSy...",
authDomain: "edupan-ppx.firebaseapp.com",
projectId: "edupan-ppx",
storageBucket: "edupan-ppx.firebasestorage.app",
messagingSenderId: "1234567890",
appId: "1:1234567890:web:abc123..."
  4. Toca Ir a la consola.
Si lo pierdes: ⚙️ Configuración del proyecto → pestaña General → abajo, en Tus apps, opción Config. Estos datos no son secretos: solo identifican el proyecto. Lo que protege la información son las reglas del paso 4.

3Activar el login (Google y correo)

  1. Menú izquierdo: Compilación → Authentication → Comenzar.
  2. Pestaña Método de acceso:
    • Correo electrónico/contraseña → activa el primer interruptor (no el de “vínculo de correo”) → Guardar.
    • Agregar proveedor nuevo → Google → actívalo, elige el correo de asistencia (el tuyo) → Guardar.
  3. Correos en español: pestaña Plantillas → ícono del lápiz junto a “Idioma de la plantilla” → Español → Guardar. Así los correos de confirmación y de “recuperar contraseña” llegan en español.

4Crear la base de datos y pegar las reglas

  1. Menú izquierdo: Compilación → Firestore Database → Crear base de datos.
  2. Si te pregunta la edición, deja Standard.
  3. Ubicación: elige una y no la cambies después (no se puede). Para Ecuador sirve us-east1 o nam5 (United States).
  4. Modo: Iniciar en modo de producción → Crear.
  5. Cuando cargue, abre la pestaña Reglas. Borra todo lo que hay.
  6. Abre el archivo firestore.rules de la carpeta con el Bloc de notas, copia todo y pégalo ahí.
  7. Toca Publicar.
Importante: en las reglas está escrito el correo de la dueña: elypiccinini298@gmail.com. Si algún día cambia, hay que cambiarlo en dos lugares: en firestore.rules (y volver a publicarlas) y en assets/js/config.js.

Qué hacen las reglas

  • Nadie entra a los datos sin iniciar sesión con un correo confirmado.
  • Solo Ely (y los administradores que ella agregue) puede registrar o cambiar datos.
  • Los correos de “solo lectura” (el jefe) pueden ver, pero el servidor rechaza cualquier cambio.
  • Cualquier otro correo, aunque cree una cuenta, no ve nada.
  • El registro de actividad no se puede editar ni borrar.

5Pegar la configuración en config.js

  1. En la carpeta edupan-ppx abre assets/js/config.js con el Bloc de notas (clic derecho → Abrir con).
  2. Reemplaza cada PEGA_AQUI… por el valor que copiaste en el paso 2. Debe quedar así (con tus valores): 
    firebase: {
  apiKey: "AIzaSy...",
  authDomain: "edupan-ppx.firebaseapp.com",
  projectId: "edupan-ppx",
  storageBucket: "edupan-ppx.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abc123...",
},
  3. Revisa que cada valor esté entre comillas y termine en coma. Guarda el archivo.

6Subir la carpeta a Netlify

  1. Entra a app.netlify.com.
  2. Add new project (o Add new site) → Deploy manually.
  3. Arrastra la carpeta completa edupan-ppx (la que tiene adentro index.html, _headers y assets). No arrastres el .zip.
  4. Netlify te da una dirección tipo https://algo-raro-123.netlify.app.
  5. Para un nombre más claro: Project configuration → Change project name → por ejemplo edupan-panel. La dirección queda https://edupan-panel.netlify.app.
El archivo _headers activa cabeceras de seguridad en Netlify (evita que la página se meta dentro de otras webs, fuerza https, etc.). No lo borres.

7Autorizar la dirección de Netlify en Firebase

  1. Firebase → Authentication → pestaña Configuración → Dominios autorizados.
  2. Agregar dominio → escribe la dirección de Netlify sin https:// ni barra final, por ejemplo: edupan-panel.netlify.app → Agregar.
Si cambias el nombre del sitio en Netlify, agrega también la dirección nueva. Sin este paso, “Entrar con Google” muestra un error de dominio no autorizado.

8Primer ingreso de Ely

  1. Abre la dirección de Netlify.
  2. Opción A (recomendada): Entrar con Google y elige elypiccinini298@gmail.com. Entra directo.
  3. Opción B: Crear cuenta con correo → correo de Ely y una contraseña de 8 caracteres o más → llega un correo de confirmación (revisa spam) → abrir el enlace → volver al panel y tocar Ya lo confirmé.
  4. La primera vez el sistema crea solo los 3 locales (Matriz, Sucursal 1 y Sucursal 2) y las categorías de gastos. Verás el panel vacío con los pasos para empezar.
  5. Empieza en este orden: Reportes diarios → Registrar día (ingresos y egresos de cada día por local; el arriendo, la luz o el agua se registran ahí como egreso con su categoría) → Personal (trabajadores y su rol de pagos).
Olvidó la contraseña: en la pantalla de entrada, ¿Olvidaste tu contraseña? → escribe el correo → llega un enlace para crear una nueva. Si entra con Google, no tiene contraseña en el panel: usa la de su cuenta de Google.

9Dar acceso al jefe (solo lectura)

  1. Ely entra a Ajustes → Usuarios, escribe el nombre y el correo del jefe → Dar acceso de solo lectura.
  2. El jefe abre la misma dirección de Netlify y entra con ese correo (con Google, o creando su cuenta con correo y confirmándola).
  3. Ve el panel, los reportes diarios, el personal y puede descargar los informes en Excel. No ve botones para registrar ni cambiar nada, y aunque lo intentara, el servidor lo rechaza.
  4. Lo que Ely registra aparece en la pantalla del jefe sin recargar.
  5. Para quitarle el acceso: Ajustes → Usuarios → Quitar acceso.

10Respaldos: que no se pierda nada

Los datos ya están en los servidores de Google, que guardan copias redundantes. Además hay dos seguros:

A. Respaldo semanal desde el panel (gratis, recomendado siempre)

  1. Ajustes → Base de datos y respaldo → Descargar respaldo. Baja un archivo respaldo-edupan-AAAA-MM-DD.json con todo.
  2. Guárdalo en Google Drive o en la computadora. El panel muestra un aviso si pasaron más de 7 días sin respaldo.
  3. Para recuperar: Restaurar un respaldo → elegir el archivo. Reemplaza productos y reportes por los del archivo (el registro de actividad y los usuarios no se tocan).

B. Copias automáticas de Firebase (opcional, con costo pequeño)

Firebase puede sacar copias automáticas diarias o semanales de toda la base y guardarlas hasta 14 semanas. Requiere el plan Blaze (pago por uso, con tarjeta). Se paga el espacio que ocupan las copias; para una panadería es poco, pero conviene poner un límite de gasto.

  1. Firebase → ⚙️ → Uso y facturación → Detalles y configuración → cambiar a Blaze. Crea una alerta de presupuesto (por ejemplo, 5 USD al mes) para que te avise si algo sube.
  2. Abre console.cloud.google.com/firestore/databases (elige el proyecto edupan-ppx) → base (default) → sección Recuperación ante desastres / Backups → Editar la programación: activa la copia diaria y/o semanal y la retención.

Fuente: Firebase · Back up and restore data (requiere Blaze; retención máxima de 14 semanas; se cobra el almacenamiento de cada copia).

11Cómo actualizar la página después

  1. Cuando te envíe una versión nueva, copia tu assets/js/config.js (el que ya tiene tus datos de Firebase) dentro de la carpeta nueva, reemplazando el que trae.
  2. Netlify → tu proyecto → Deploys → arrastra la carpeta nueva al recuadro “Drag and drop your project folder here”.
  3. Los datos no se tocan: viven en Firebase, no en Netlify.

12Si algo falla

Lo que vesQué hacer
“Falta conectar Firebase”El config.js todavía tiene PEGA_AQUI o se subió la carpeta vieja. Repite el paso 5 y vuelve a subir.
Página en blancoRevisa que en config.js no falte una coma o comilla. En la computadora: F12 → pestaña Console → mándame captura del error en rojo.
“Esta dirección web no está autorizada en Firebase”Paso 7: agrega el dominio de Netlify en Dominios autorizados.
“Este método de acceso no está activado”Paso 3: activa Correo/contraseña y Google.
“La base de datos rechazó la operación” o “No se pudo abrir el panel”Paso 4: revisa que las reglas estén publicadas y que el correo de la dueña en firestore.rules sea exactamente el mismo que en config.js.
“No se encontró la base de datos”Falta crear Firestore (paso 4) o el projectId de config.js no coincide.
“Sin acceso” con el correo del jefeEly debe agregarlo en Ajustes → Usuarios con el mismo correo exacto con el que él entra.
No llega el correo de confirmación o de contraseñaRevisar spam/promociones. Con “Reenviar el correo” se manda otro. Los correos salen de noreply@…firebaseapp.com.
La ventana de Google se cierra o no abrePermitir ventanas emergentes para el sitio; en celular, el sistema intenta abrir Google en la misma pestaña.
Aparece “No se guardó” abajo a la derechaSe cortó internet o la sesión venció. Revisa la conexión; el siguiente cambio vuelve a enviar lo pendiente. Si persiste, cierra sesión y vuelve a entrar.
El login de Google no funciona pero el de correo sí, y el error menciona “Content Security Policy”Abre _headers, borra la línea que empieza con Content-Security-Policy y vuelve a subir. Avísame para ajustarla.
Cuando encuentres un error, envíame: qué estabas haciendo, una captura de la pantalla y, si puedes, la captura de la consola (F12 → Console).
